# Beeline tariff campaign agent — MVP

Hackathon team repository for syla.

Рабочий агент для кейса HackAlem AI. Он использует только предоставленные данные и публичный интерфейс `env`; скрытые эффекты среды не читает.

## Запуск

```bash
pip install -r requirements.txt
python local_eval.py
python local_eval.py --runs 10
python make_submission.py
python -m unittest discover -s tests
```

Дополнительная проверка устойчивости (не часть сдаваемого агента):

```bash
python stress_eval.py --scenarios 20 --change-sd 0.30
python stress_eval.py --scenarios 20 --change-sd 0.30 --change-bias -0.30
```

`stress_eval.py` меняет синтетические эффекты переходов и отдельно шум пилотов. Эти сценарии помогают найти слабые места, но не воспроизводят скрытую модель судейства и не являются прогнозом балла.
Флаг `--risk-penalty` позволяет сравнить осторожность финального выбора; рабочий агент использует значение `1.0` для проверенных пилотами групп.

Для сдачи нужны `agent.py`, `submission.csv` и `requirements.txt`. Файл `submission.csv` генерируется из текущего агента, вручную его не редактировать.

## Локальное демо для жюри

```bash
python dashboard_server.py
```

Откройте `http://127.0.0.1:8765`. В разделе «Данные» загрузите три CSV: базу абонентов, справочник тарифов и историю переходов. Требования к колонкам и пустые CSV-шаблоны доступны на экране. Поддерживаются UTF-8, разделитель запятая или точка с запятой, до 15 МБ на файл / 30 МБ суммарно. Лимиты: 100 000 абонентов, 100 тарифов, 100 000 переходов.

Проверка выявляет дубли ID, неизвестные тарифы, неверные сегменты и числовые значения. Строки базы без текущего тарифа или ARPU-сегмента исключаются с предупреждением; пропуски потребления остаются неизвестными. После проверки нажмите «Построить план». Расчёт использует именно загруженную историю и базу; CSV соответствует выбранному набору и сценарию. Кнопка «Посмотреть на данных кейса» открывает прежнее демо.

**Оба режима симулируют пилоты по истории переходов.** Это не измеренный отклик реальных абонентов и не прогноз скрытого судейства. Загрузка истории не заменяет контрольные рассылки. Приложение не отправляет сообщения; фиксированные лимиты кампаний и каналов взяты из кейса. Для внешних данных скачивается `campaign_plan.csv`, для данных кейса — `submission.csv`.

Загрузки обрабатываются локально и хранятся только в памяти процесса (последние четыре набора). После перезапуска сервера их нужно загрузить заново. Файлы проекта и исходные CSV не перезаписываются. Сервер привязан к `127.0.0.1`; это локальное MVP, не многопользовательский сервис.

В плане видны расходы и контакты отдельно для пилотов, финальных кампаний и каждого использованного канала, включая бесплатный push. Карточка кампании объясняет обрезку по лимиту группы, общему охвату или бюджету. Кнопки отчёта JSON/Markdown выгружают именно отображаемый расчёт с seed, версией модели и отметкой симуляции; без ID абонентов, исходных имён файлов и токена загрузки. CSV кампаний остаётся отдельным экспортом.

### Объяснение плана и черновики коммуникаций

Блок «Что меняет план» сравнивает базовую выручку без кампаний с результатом плана в той же симуляции: база + net ARPU после затрат. Это не сравнение с работой маркетолога и не бухгалтерская прибыль. Воронка считает уникальные проверенные гипотезы, отдельно показывает отклонённые, выбранные и не вошедшие в портфель; повторный пилот не считается новой гипотезой. Кампании без пилота отмечены отдельно.

В карточке кампании вкладка «Текст кампании» предлагает три переключаемых черновика для выбранного канала с кнопкой копирования. Локальный модуль `campaign_creatives.py` использует только проверенные цену и пакет интернета из справочника тарифов; не придумывает скидки, скорость, экономию или гарантии. При неполных данных текст не генерируется. Если браузер запрещает копирование, появляется поле для ручного копирования.

Это детерминированные шаблоны, **не LLM и не отправка сообщений**: API и платные сервисы не используются. Примеры на данных кейса синтетические; перед реальной рассылкой нужны проверка условий тарифа и согласование текста. Черновики не меняют агент, `submission.csv` или расчёт метрик и не включаются в агрегированный JSON/Markdown-отчёт.

### Журнал «Прогноз → факт»

После построения плана интерфейс сохраняет агрегированные результаты всех пилотов, включая повторные и отклонённые гипотезы. В журнале видны прогноз **до** наблюдения, шумный результат симуляции, обновлённая оценка, размер пилота, затраты и итог гипотезы. CSV выгружается для выбранного расчёта с явной отметкой `provenance=simulation`.

Журнал хранится локально в `.local/pilot_history.sqlite3` и переживает перезапуск сервера. Исходные базы, ID абонентов и имена загруженных файлов в него не записываются. `.local/` исключён из Git. Повтор того же расчёта не создаёт дубликат; версия алгоритма и отпечаток входных данных различают изменившиеся расчёты. Интерфейс показывает 100 последних записей.

Это аудит обновлений внутри прогона, **не обучение между запусками**. Архив не подмешивается в prior агента, и симулированные пилоты не выдаются за реальные кампании. Среднее абсолютное отклонение от наблюдения описывает шумные пилоты, а не качество модели на отложенной выборке. Для следующего этапа обучения нужны реальные результаты и отдельная проверка новой модели.

## Что делает агент

1. Строит осторожную предварительную оценку переходов по историческим данным другой аудитории.
2. Ранжирует до 16 непересекающихся групп «текущий тариф × ARPU-сегмент» и проводит SMS-пилоты, пока не найдёт достаточно экономически перспективных групп или не достигнет лимита.
3. Отсекает уверенно убыточные гипотезы; до четырёх повторных пилотов направляет туда, где дополнительная информация может изменить решение о запуске.
4. Сравнивает `push`, `sms` и `digital_ads`, выбирает до 10 кампаний с учётом оставшихся контактов и бюджета. Если полной группе не хватает лимита, оценивает ту часть аудитории, которую скорер возьмёт первой по `ID_NUMBER`. `call` не экстраполируется из SMS: конверсия может достичь потолка, а её истинное значение в новой аудитории неизвестно.
5. При свободных слотах может добрать небольшие группы без отдельного пилота, только если осторожная оценка по историческому prior положительна.

Оценка `local_eval.py` показывает работу на мок-среде, **не прогноз балла на скрытом судействе**. Текущая версия использует только ARPU-сегмент и текущий тариф; сегменты трафика и звонков и прямые пилоты других каналов остаются направлениями для следующего этапа. Небольшие группы без пилота особенно чувствительны к расхождению истории и скрытой аудитории.

Некорректный ответ пилота не меняет posterior; разведка продолжает проверять остальные группы в пределах лимитов. Нечисловой/отрицательный ARPU исключает всю затронутую группу: удаление только плохих строк нарушило бы совпадение с ID-порядком скорера. Повреждённая история даёт запасной prior. Финальная кампания с неположительной осторожной оценкой не запускается ради заполнения списка.

На выданном наборе проверяются требования ТЗ: 1–10 финальных кампаний и использование пилотов. На вырожденных внешних данных возможен пустой план или план только малых групп без пилота — это безопасный режим MVP, **не гарантия соответствия must-have хакатона для любых входов**.

## Сравнение и перенос улучшений из веток

Аудит шести веток, принятые решения и ограничения: [BRANCH_INTEGRATION.md](BRANCH_INTEGRATION.md). Экспериментальный агент и Streamlit-интерфейс не заменяют текущий продукт; перенесены совместимые части.

```bash
python benchmark_agents.py --baseline-ref 1cb2ba6 --runs 10
# При необходимости сохранить подробный локальный отчёт:
python benchmark_agents.py --baseline-ref 1cb2ba6 --runs 20 --seed-start 2000 --output benchmark.json
```

Сравнивается `agent.py` указанной Git-ревизии с текущим рабочим файлом на одинаковых seed и неизменной среде. Отчёт содержит хеши кода/данных, Min/Mean/Median/p05, парную дельту, ошибки и нарушения. Пустые планы и неудачные прогоны не скрываются. Запускайте только доверенные ревизии: это исполнение кода.

Перенос против `1cb2ba6`, seed 0–9: среднее **3 584 479 → 4 003 094**, минимум **2 804 837 → 3 345 859**, медиана **3 610 986 → 4 136 349** у.е.; 9/10 парных побед. Более дорогая реклама увеличивает расход бюджета. При сильном отрицательном сдвиге среднее улучшилось, но худший результат ухудшился — подробности в отчёте аудита. Это эмпирическое сравнение синтетики, не гарантия выигрыша на скрытых эффектах.

## Эксперимент с обучаемым prior

Ниже — результаты отдельного эксперимента до добавления `digital_ads` (снимок `b3706d1`), а не метрики последней версии.

`model_experiment.py` обучает регуляризованную линейную модель на истории уже совершённых смен тарифа и проверяет её на пяти фолдах, разделённых по ID абонента. Используются только выданные участникам данные и NumPy; NVIDIA GPU для такого объёма не требуется. `compare_agents.py` сравнивает рабочий агент с вариантом, где обученная модель даёт предварительную оценку, а пилоты и ограничения работают как раньше.

```bash
python model_experiment.py
python compare_agents.py
```

Результат на отложенных клиентах: RMSE изменения ARPU 0.9917 у текущего предварительного правила против 0.9531 у ridge-модели (alpha=100). Это **не** точность отклика на предложение и не оценка скрытого судейства: в истории нет отказов от кампаний.

Парное сравнение на 10 seed локального мока: средний net ARPU 3,584,479 у baseline и 3,611,202 у модели; побед 5/10. На 20 синтетических сценариях со сдвигом эффекта SD=0.30 модель проиграла baseline при нулевом сдвиге (3,703,166 против 4,095,513), но выиграла при сильном отрицательном смещении -0.60 (221,146 против 116,579). Эти эффекты заданы нами для стресс-проверки, не являются моделью судейства. Из-за неоднозначного результата **сдаваемый `Agent()` по умолчанию оставлен на проверенном prior**; обученный вариант доступен только как эксперимент через `Agent(prior_provider=ml_prior.learned_priors)`.

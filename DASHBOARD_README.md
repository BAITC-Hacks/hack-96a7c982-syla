# Beeline Campaign AI — dashboard

Локальный Streamlit-интерфейс для просмотра рекомендаций агента, результатов локального скорера и истории пилотов. Он работает только с синтетическими данными и не подключается к системам Beeline.

## Запуск

```bash
python -m pip install -r requirements-dashboard.txt
python -m streamlit run dashboard.py
```

По умолчанию открывается детерминированный демоотчёт `demo/dashboard_report.json`. Переключатель «Отчёт / Демо» явно показывает режим; фиктивные данные не подставляются при ошибке незаметно.

## Источники и локальный расчёт

- **Демонстрационные данные** — согласованный пример из шести кампаний, не benchmark.
- **Загруженный отчёт** — JSON до 5 МБ. Адаптер понимает формат `PITCH_REPORT.json`, а отсутствующие поля показывает как «Нет данных».
- **Локальная симуляция** — кнопка создаёт mock-среду, вызывает `Agent.act()` ровно один раз, скорит финальные кампании и пилоты этого же запуска и пишет UI-копию в `artifacts/dashboard/latest_report.json`. `submission.csv` не изменяется.

Опционально отчёт может содержать `schema_version`, `source`, `seed`, `agent_commit`, `generated_at` и `pilot_history`. Их отсутствие не считается ошибкой. Загрузка отчёта candidate-final предназначена только для просмотра: кнопка расчёта всегда использует `agent.py`, установленный в текущей рабочей копии, и не скачивает код из других веток.

Ошибка загрузки или расчёта оставляет последний успешный отчёт на экране и явно помечается. Выбор строки, фильтрация и вкладки не запускают агента повторно.

## Метрики

- **Чистый прирост** — `gross_arpu_lift - total_cost`, итог локального скорера после дедупликации клиентов.
- **ROI** — `gross_arpu_lift / total_cost`, как в `scoring_core.py`; при нулевых расходах не определён.
- **Расходы и контакты** включают пилоты, если отчёт сформирован локальным runner или корректно передаёт итоги скорера.
- Relative/posterior lift и интервалы отображаются в процентах; денежные эффекты — в условных единицах. 95% CI — модельный интервал неопределённости, не гарантия причинного эффекта.

Лимиты исходного кейса остаются в штатном скорере: бюджет 100 000 у.е., 15 000 контактов вместе с пилотами, максимум 20 пилотов по 10–200 контактов, до 10 кампаний и до 5 000 контактов на кампанию. Dashboard их не подменяет. Пустой план безопасно отображается, но не объявляется готовым к сдаче.

## Экспорт

Раздел «Экспорт» выдаёт CSV кампаний, стандартный JSON без `NaN`/`Infinity` и Markdown-резюме. Все форматы содержат источник и seed (если известен). CSV — аналитический экспорт UI, **не** официальный `submission.csv`; официальный файл по-прежнему формируется `make_submission.py`.

## Перенос UI на финальную версию агента

Перенесите только `dashboard.py`, `dashboard_ui/`, `.streamlit/config.toml`, `requirements-dashboard.txt`, `DASHBOARD_README.md`, `demo/dashboard_report.json` и `tests/dashboard/`. Файлы алгоритма и скоринга не требуются в патче: runner импортирует их публичные функции из выбранной финальной ветки.

## Ограничения

Загруженный старый pitch-отчёт может не содержать контакты, расходы по каждой кампании или подробную историю пилотов; интерфейс честно показывает отсутствие данных. Локальная модель синтетическая, поэтому её результаты нельзя трактовать как реальные бизнес-показатели.

## Чек-лист визуальной проверки

На ноутбуке откройте `http://localhost:8501` и проверьте:

1. при ширине 1440×900 видны header, KPI, начало таблицы и графиков;
2. при ширине около 390 px блоки складываются вертикально, а таблица прокручивается;
3. «Демо → Отчёт → Демо» сохраняет последний загруженный отчёт;
4. фильтр канала, выбор строки и вкладка «Результаты пилотов» не запускают расчёт;
5. отрицательная кампания остаётся видимой и показывает предупреждение;
6. расходы и контакты разделены на «финал / пилоты / всего»;
7. режим презентации не скрывает отрицательные значения и предупреждения;
8. CSV, JSON и Markdown скачиваются для текущего отображаемого источника.

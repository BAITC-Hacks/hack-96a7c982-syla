## Почему не объединены ветки целиком

- Экспериментальные версии теряют возможность передавать историю загруженного набора в prior, а также меняют работающий выбор повторных пилотов по стоимости информации.
- В одной реализации метаданных кампании `mean/std` после выбора относятся к последнему рассмотренному варианту, а не к победителю. Эти интервалы и оценки не переносились.
- `call` может достигнуть потолка вероятности конверсии. Конверсия из истории другой аудитории не даёт точной поправки для целевой базы. Каналы push/SMS/digital_ads с множителями до 1 допускают линейный пересчёт при валидной вероятности конверсии.
- Запасной агент из веток запускает кампанию по одному положительному шумному наблюдению без проверки неопределённости. Это не принято.
- Старый pitch-генератор запускает агента дважды. Новый экспорт использует единый снимок отображаемого расчёта, без повторного запуска и без приватных полей загрузки.
- Старые benchmark-отчёты сравнивают `0b89100`, а не текущий `main`. Их цифры не использованы как доказательство превосходства над `1cb2ba6`.

## Парная проверка итогового агента

Команда для воспроизведения на текущем checkout:

```bash
python benchmark_agents.py --baseline-ref 1cb2ba6 --runs 10
python -m unittest discover -s tests
python local_eval.py --runs 10
python make_submission.py
```

`benchmark_agents.py` исполняет только доверенные снимки `agent.py`; исходные публичные данные, среда и скорер одинаковы для обеих версий. В JSON записываются хеши кода, данных и зависимых модулей; ошибки и пустые планы не исключаются из отчёта.

## Стресс и ограничения

Дополнительно применён существующий `stress_eval.evaluate` с явно синтетическими сдвигами эффекта. Среда и скорер не менялись. Для сильного отрицательного сдвига: SD=0.30, bias=−0.60, seed 2000–2019:

| Метрика | Main `1cb2ba6` | Digital_ads + защиты |
|---|---:|---:|
| Min | −527 246 | −641 280 |
| Mean | 276 096 | 514 571 |
| Median | 355 007 | 647 434 |
| p05 | −464 436 | −497 729 |
| Положительных | 11/20 | 15/20 |

Побед 18/20, но худший исход и p05 **ухудшились**. При SD=0.30 без смещения среднее тоже выросло, а минимум снизился с 1 655 822 до 1 126 950. Выбор более дорогого канала не является гарантией устойчивости на любом распределении. Результаты не предсказывают скрытый балл, не являются реальными показателями Beeline и не доказывают причинный uplift.

Guide требует 1–10 финальных кампаний и использование пилотов. На выданных данных это проверено. На произвольных плохих входах агент может воздержаться от запуска либо выбрать только малые группы без пилота; этот безопасный режим продукта нельзя выдавать за выполнение must-have для любых данных.

## Интерфейс и артефакты

- Ресурсы берутся из фактических строк скорера: пилоты, финал и каждый канал. Контакты не означают уникальных клиентов; повторные обращения тоже расходуют лимит.
- Объяснения ограничения охвата показывают конкретный флаг скорера: 5 000 на кампанию, общий охват или бюджет.
- JSON/Markdown содержат только агрегаты и provenance=simulation. В них нет ID абонентов, исходных имён файлов или токена загрузки. Это не замена `submission.csv`.
- Источник данных, загрузчик и журнал сохраняются. История журнала не превращается в обучающую выборку автоматически.
- `submission.csv` заново сгенерирован текущим агентом с seed 42; исходные правила скоринга и файлы среды не изменены.

Проверено: 50 unittest-тестов, `local_eval.py --runs 10`, синтаксис JavaScript, совпадение dashboard/submission, визуальная компоновка и отсутствие ошибок браузера. Содержимое JSON/Markdown проверено тестами; завершение скачивания через встроенный браузер автоматическая проверка подтвердить не смогла (тайм-аут события загрузки).
